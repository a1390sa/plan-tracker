# دليل النشر والتشغيل — نظام متابعة تنفيذ الخطط

> هذا الدليل موجّه لك مباشرة إذا كنت المسؤول عن تجهيز نسخة مستقلة من النظام. لا يفترض
> أي خبرة تقنية سابقة — اتبع الخطوات بالترتيب، وستحصل بنهايتها على نظام كامل يعمل،
> بقاعدة بيانات وموقع وبريد خاصين بك، **منفصلين تماماً عن أي جهة أخرى تستخدم نفس
> النظام**. التكلفة الشهرية: صفر ريال، ضمن الحدود المجانية للخدمات الثلاث المستخدمة.

## قبل ما تبدأ

- بريد إلكتروني تسجّل فيه بالخدمات الثلاث (Supabase، Vercel، Resend).
- جهاز كمبيوتر (ويندوز أو ماك) — تحتاجه لخطوة واحدة فقط بمنتصف الدليل (خطوة 3).
- حوالي 40-45 دقيقة إجمالاً، موزّعة على 5 خطوات.

لا تحتاج تعرف البرمجة. كل خطوة فيها نسخ-ولصق فقط.

---

## الخطوة 1: قاعدة البيانات (Supabase) — 10 دقائق

قاعدة البيانات هي المكان اللي تُحفظ فيه كل بياناتك (الخطط، المهام، المستخدمون) —
مستقلة بالكامل عن أي نسخة أخرى من النظام.

1. روح لموقع **supabase.com** وسجّل حساب جديد (بريدك الإلكتروني كافي).
2. اضغط **"New Project"**.
3. املأ:
   - **Name**: اسم يدلّ على جهتك، مثلاً `my-org-plan-tracker`
   - **Database Password**: كلمة مرور قوية — **احفظها في مكان آمن**، نادراً ما تحتاجها لاحقاً لكن لا تفقدها
   - **Region**: اختر الأقرب جغرافياً لك (مثلاً Frankfurt للشرق الأوسط)
4. اضغط **Create new project** وانتظر دقيقة أو دقيقتين لين يجهز.

### تنفيذ هيكل قاعدة البيانات
5. من القائمة اليسرى اضغط **SQL Editor** ← **New query**.
6. افتح هذا الرابط من النظام نفسه، أو حمّل ملف `schema.sql` من مطوّر النظام، وانسخ
   **كل محتواه**.
7. الصقه بصندوق SQL Editor واضغط **Run** (أو Ctrl+Enter). لازم تشوف **"Success. No
   rows returned"**.

### صلاحية مدير النظام (خطوة منفصلة إلزامية)
8. اضغط **New query** مرة ثانية (استعلام منفصل).
9. انسخ محتوى ملف `admin_policy.sql` والصقه، واضغط **Run**. هذه الصلاحية ضرورية
   حتى يقدر مدير النظام لاحقاً يرقّي أو يدير حسابات الموظفين من تبويب الإعدادات.

### تفعيل تسجيل الدخول
10. من القائمة اليسرى اضغط **Authentication** ← **Sign In / Providers**.
11. تأكد أن **Email** مفعّل (غالباً مفعّل افتراضياً).

### حفظ قيمتين مهمتين
12. اضغط **Settings** (⚙️ بالأسفل) ← **API**.
13. انسخ هاتين القيمتين واحفظهما بملاحظة — تحتاجهما بخطوة 4:
    - **Project URL** (يبدأ بـ `https://` وينتهي بـ `.supabase.co`)
    - **Publishable key** (يبدأ بـ `sb_publishable_...`)

## الخطوة 2: البريد الإلكتروني (Resend) — 5 دقائق

Resend هي الخدمة اللي ترسل تنبيهات البريد اليومية (تذكير المهام، التأخر، إلخ).

1. روح لموقع **resend.com** وسجّل حساب جديد.
2. من القائمة اليسرى اضغط **API Keys** ← **Create API Key**.
3. اعطه اسماً (مثلاً `plan-tracker-notifications`)، واترك الصلاحيات الافتراضية.
4. **انسخ المفتاح فوراً واحفظه** — يبدأ بـ `re_...` ويظهر **مرة واحدة فقط**؛ إذا
   أغلقت الصفحة قبل نسخه تضطر تسوي مفتاحاً جديداً.

(اختياري لاحقاً: وثّق نطاق بريدك الخاص من **Domains** لترسل الرسائل باسم جهتك؛ إلى
حينه يعمل الإرسال من عنوان تجريبي `onboarding@resend.dev`.)

## الخطوة 3: نشر دالة التنبيهات اليومية — 15 دقيقة

هذه الخطوة الوحيدة اللي تحتاج موجّه أوامر (Terminal / Command Prompt) بجهازك.

### أ) تثبيت Node.js (إذا ما عندك)
1. روح لموقع **nodejs.org** وحمّل نسخة **LTS**.
2. ثبّتها بالإعدادات الافتراضية (Next، Next، Next...).
3. افتح موجّه الأوامر وتأكد:
   - **Windows:** اضغط Start واكتب `cmd`
   - **Mac:** افتح Terminal من Launchpad
4. اكتب `node -v` واضغط Enter — لازم يطلع رقم إصدار (مثل `v20.x.x`).

### ب) تنزيل ملفات المشروع
5. حمّل نسخة من ملفات النظام (مجلد المشروع كاملاً) من الجهة اللي سلّمتك إياه، وفك
   الضغط عنه في مكان بسيط — **يُفضّل مباشرة بالقرص C:\ (ويندوز)** وليس داخل مجلد
   OneDrive أو سطح المكتب، لتفادي مشاكل مزامنة الملفات أثناء الخطوات التالية.

### ج) فتح موجّه الأوامر داخل مجلد المشروع
6. افتح مجلد المشروع في File Explorer.
7. اضغط بشريط العنوان بأعلى النافذة، امسح المسار، اكتب `cmd`، واضغط Enter.
8. تأكد إنك بالمكان الصحيح بكتابة `dir` (أو `ls` بماك) — لازم تشوف ملفات مثل
   `package.json` و`supabase`.

### د) تثبيت أداة Supabase وتسجيل الدخول
9. اكتب:
   ```
   npm install -g supabase
   ```
10. بعد ما يخلص، اكتب:
    ```
    supabase login
    ```
    بيفتح لك متصفح — سجّل دخول لنفس حساب Supabase ووافق (Authorize). يطلع لك رمز
    تحقق بالمتصفح: انسخه، ارجع لموجّه الأوامر بسرعة، واضغط **كليك يمين داخل النافذة
    السوداء نفسها** للصق (مو Ctrl+V — ما يشتغل بكل أنواع موجّه الأوامر)، ثم Enter.

### هـ) الربط ونشر الدالة
11. اربط المشروع (بدّل `your-project-ref` برقم مشروعك من Settings > General > Project ID):
    ```
    supabase link --project-ref your-project-ref
    ```
    إذا طلب كلمة مرور قاعدة البيانات، أدخل اللي حفظتها بخطوة 1.
12. اضبط الأسرار الثلاثة (بدّل القيم بين `<>` بقيمك الفعلية، **بدون مسافات حول
    علامة =**):
    ```
    supabase secrets set RESEND_API_KEY=<مفتاح_Resend_من_خطوة_2>
    supabase secrets set MAIL_FROM=onboarding@resend.dev
    supabase secrets set APP_URL=https://example.com
    ```
    (`APP_URL` قيمة مؤقتة الآن — بنعدّلها بخطوة 4 بعد ما يصير عندك رابط موقع فعلي.)
13. انشر الدالة:
    ```
    supabase functions deploy send-notifications --no-verify-jwt
    ```

**ملاحظة:** إذا طلعت رسالة خطأ غريبة (زي "Out of memory" أو كرش مفاجئ)، هذا عطل
مؤقت بالأداة نفسها — فقط أعد تنفيذ نفس الأمر مرة ثانية، يشتغل غالباً بالمحاولة الثانية.

### و) جدولة الإرسال اليومي
14. ارجع للوحة Supabase ← **SQL Editor** ← **New query**، والصق (بدّل YOUR_PROJECT_REF
    برقم مشروعك):
    ```sql
    select cron.schedule(
      'daily-notifications', '0 3 * * *',
      $$ select net.http_post(
           url := 'https://YOUR_PROJECT_REF.supabase.co/functions/v1/send-notifications',
           headers := '{"Content-Type": "application/json"}'::jsonb
         ) $$
    );
    ```
15. اضغط **Run**. (إذا طلعت رسالة عن امتداد غير مفعّل: فعّل `pg_cron` و`pg_net` من
    **Database > Extensions** ثم أعد تنفيذ الاستعلام.)

هذا يعني التنبيهات ترسل تلقائياً الساعة 6 صباحاً بتوقيت الرياض يومياً.

## الخطوة 4: نشر الموقع (Vercel) — 10 دقائق

1. روح لموقع **vercel.com** وسجّل حساب (الأسهل: **"Continue with GitHub"** إذا عندك
   حساب GitHub).
2. اضغط **Add New...** ← **Project**.
3. استورد ملفات المشروع كمستودع جديد (أو اربطه بمستودع GitHub إذا عندك واحد).
4. بشاشة الإعداد، قبل الضغط على Deploy، أضف قسم **Environment Variables**:
   - الاسم: `VITE_SUPABASE_URL` — القيمة: رابط Project URL اللي حفظته بخطوة 1
   - الاسم: `VITE_SUPABASE_ANON_KEY` — القيمة: Publishable key اللي حفظته بخطوة 1
5. اضغط **Deploy** وانتظر دقيقة أو دقيقتين.
6. انسخ رابط موقعك الناتج (يشبه `https://your-app.vercel.app`).

### ربط الرابط بإعدادات الدخول
7. ارجع للوحة Supabase ← **Authentication** ← **URL Configuration**.
8. بحقل **Site URL** الصق رابط موقعك.
9. بحقل **Redirect URLs** اضغط **Add URL** والصق نفس الرابط متبوعاً بـ `/**`
   (مثال: `https://your-app.vercel.app/**`).
10. اضغط **Save**.

### تحديث رابط التنبيهات بالقيمة الحقيقية
11. ارجع لموجّه الأوامر (نفس نافذة خطوة 3) ونفّذ:
    ```
    supabase secrets set APP_URL=https://your-app.vercel.app
    ```
    (بدّل الرابط برابط موقعك الحقيقي.)

## الخطوة 5: التشغيل الأول — 5 دقائق

1. افتح رابط موقعك واضغط **"لا تملك حساباً؟ أنشئ حساباً"**.
2. سجّل اسمك وبريدك وكلمة مرور — **هذا الحساب لازم يُنشأ من الموقع نفسه، وليس من
   لوحة Supabase**، وإلا ما يُنشأ ملفه الشخصي بشكل صحيح.
3. إذا طلب تأكيد بريد، افحص بريدك واضغط رابط التأكيد.
4. رقّي حسابك لـ«مدير نظام»: ارجع للوحة Supabase ← **Table Editor** ← جدول
   `profiles` ← دوّر على صفك ← اضغط ضغطتين على خلية `is_admin` واختر `true`.
5. حمّل القالب الابتدائي الفارغ من داخل النظام نفسه (تبويب **الإعدادات** ← قسم
   «الملفات والأدلة»)، ثم ارفعه من تبويب **خططي**.
6. بعد الرفع، عدّل كل شي حسب خطتك الفعلية من تبويب **«إدارة الخطة»** (ظاهر لمدير
   الخطة فقط) — أسماء المؤشرات، المهام، المستهدفات — كلها قابلة للتعديل مباشرة من
   الواجهة، بلا حاجة ترجع لملف إكسل مرة ثانية.
7. أضف بقية فريقك من تبويب **الأعضاء** ببريدهم (لازم كل عضو ينشئ حسابه بنفسه من
   رابط الموقع أولاً قبل ما تقدر تضيفه)، وأسند لكل مهمة مسؤولاً رئيساً ومساندين من
   **لوحة المتابعة**.

🎉 نظامك جاهز ويعمل بشكل مستقل تماماً.

## مهام الصيانة الشهرية (نصف ساعة)

1. فحص استهلاك Supabase (Database/Storage) و Resend (عدد الرسائل المرسلة) من
   لوحتي الخدمتين — للتأكد إنك لسا ضمن الحدود المجانية.
2. التأكد من عمل الجدولة اليومية: Supabase ← **Edge Functions** ← **Logs**.
3. أخذ نسخة احتياطية يدوية عند الحاجة: Supabase ← **Database** ← **Backups**.

## استكشاف الأخطاء الشائعة

| العرض | السبب الأرجح | الحل |
|---|---|---|
| «الملف لا يطابق القالب» عند رفع خطة | بنية الإكسل غير متوافقة | استخدم القالب الابتدائي الفارغ من تبويب الإعدادات كنقطة بداية |
| لا تصل رسائل التنبيهات | مفتاح Resend أو الجدولة غير صحيحة | راجع Secrets بموجّه الأوامر، وتأكد من سجل الجدولة بـ SQL: `select * from cron.job;` |
| «بيانات الدخول غير صحيحة» عند أول تسجيل | تأكيد البريد مفعّل ولم يُؤكَّد | افحص بريدك لرابط التأكيد، أو عطّل التأكيد مؤقتاً من Authentication > Sign In / Providers |
| عضو ما يشوف خطة معيّنة | ليس عضواً فيها | أضفه من تبويب «الأعضاء» بتلك الخطة تحديداً |
| `'supabase' is not recognized` بموجّه الأوامر | الأداة ما تثبّتت بهالجلسة | أعد `npm install -g supabase` بنفس النافذة |
| `AlreadyExists` عند تنفيذ `supabase link` | ملف مؤقت متبقٍّ من محاولة سابقة | نفّذ `rmdir /s /q supabase\.temp` (ويندوز) ثم أعد `supabase link` |
| حذف خطة لا يعمل بصمت | المستخدم ليس صاحب الخطة ولا مدير نظام | رقّي الحساب لمدير نظام، أو اطلب من صاحب الخطة الحذف |

## التشغيل اليومي (لا يحتاج معرفة تقنية)
راجع **«دليل استخدام النظام»** الآخر (متوفر بنفس قسم «الملفات والأدلة» بتبويب
الإعدادات) — يشرح كيف يستخدم الموظفون ومدراء الخطط النظام يومياً.
