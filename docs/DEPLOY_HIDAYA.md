# نسخة مستقلة لجمعية هداية — دليل النشر والتشغيل

> هذا دليل نشر **نسخة معزولة تماماً** من نظام متابعة تنفيذ الخطط، خاصة بجمعية هداية،
> منفصلة كلياً عن نسخة مؤسسة غيث الخيرية (قاعدة بيانات مستقلة، نشر مستقل، مستخدمون مستقلون).
> الشيفرة نفسها في هذا المستودع — الفرق فقط في مشروعي Supabase وVercel المستخدَمين.

**التكلفة الشهرية: صفر** ضمن الخطط المجانية (Supabase + Vercel + Resend)، بنفس حدود
نسخة غيث.

---

## الخطوة 1: قاعدة بيانات مستقلة (Supabase) — 10 دقائق

1. أنشئ **مشروع Supabase جديداً** خاصاً بهداية (لا تستخدم مشروع غيث). اختر منطقة قريبة
   مثل Frankfurt.
2. من **SQL Editor > New query** الصق محتوى `supabase/schema.sql` كاملاً ثم **Run**.
3. في استعلام جديد الصق محتوى `supabase/admin_policy.sql` ثم **Run** — هذه الصلاحية
   لازمة حتى يقدر مدير النظام لاحقاً يرقّي/يدير حسابات موظفي هداية من تبويب الإعدادات.
4. من **Authentication > Providers** تأكد أن Email مفعّل.
5. من **Settings > API** انسخ `Project URL` و`anon public key` (المفتاح الجديد يبدأ
   بصيغة `sb_publishable_...`).

## الخطوة 2: البريد (Resend) — 5 دقائق

نفس خطوات نسخة غيث، لكن بحساب/مفتاح مستقل إن أمكن (أو مفتاح Resend نفسه إذا كان
الحساب يُدار مركزياً — المهم أن `MAIL_FROM` و`APP_URL` أدناه يخصّان هداية).

1. أنشئ حساباً في resend.com (أو استخدم حساباً موجوداً) ومن **API Keys** أنشئ مفتاحاً.
2. (اختياري لاحقاً) وثّق نطاق جهة هداية لإرسال الرسائل باسمها؛ إلى حينه يعمل الإرسال
   من `onboarding@resend.dev`.

## الخطوة 3: وظيفة التنبيهات اليومية — 10 دقائق

```bash
npm install -g supabase
supabase login
cd plan-tracker
supabase link --project-ref <معرف مشروع هداية على Supabase>
supabase secrets set RESEND_API_KEY=<مفتاح Resend>
supabase secrets set MAIL_FROM=onboarding@resend.dev
supabase secrets set APP_URL=<رابط نشر هداية بعد الخطوة 4>
supabase functions deploy send-notifications --no-verify-jwt
```

ثم الجدولة اليومية من **SQL Editor** (استبدل YOUR_PROJECT_REF بمعرّف مشروع هداية):

```sql
select cron.schedule(
  'daily-notifications', '0 3 * * *',
  $$ select net.http_post(
       url := 'https://YOUR_PROJECT_REF.supabase.co/functions/v1/send-notifications',
       headers := '{"Content-Type": "application/json"}'::jsonb
     ) $$
);
```

(فعّل `pg_cron` و`pg_net` من Database > Extensions إن ظهرت رسالة عن امتداد غير مفعّل.)

## الخطوة 4: نشر الواجهة (Vercel) — 10 دقائق

1. ادفع هذا المستودع (بحالته الحالية) إلى **مشروع Vercel جديد ومستقل** خاص بهداية —
   لا تُضِف بيئة هداية إلى مشروع Vercel الخاص بغيث.
2. في **Environment Variables** أضف:
   - `VITE_SUPABASE_URL` = رابط مشروع Supabase الخاص بهداية
   - `VITE_SUPABASE_ANON_KEY` = المفتاح العلني لمشروع هداية
3. اضغط **Deploy**. الرابط الناتج هو نظام هداية المستقل.
4. ارجع لـ Supabase > **Authentication > URL Configuration** وضع رابط Vercel هذا في
   Site URL وRedirect URLs (مع `/**`).

## الخطوة 5: التشغيل الأول — 5 دقائق

1. أنشئ حسابك من رابط نظام هداية (وليس من لوحة Supabase — **كل** حساب يُنشأ من رابط
   التطبيق نفسه، وإلا لن يُنشأ ملفه الشخصي وستفشل عمليات RLS).
2. اجعل حسابك «مدير نظام»: Supabase > **Table Editor** > `profiles` > `is_admin = true`.
3. ارفع قالب هداية الجاهز: `templates/خطة_هداية_قالب_تنفيذي.xlsx`
   (24 شهراً هجرياً، 5 مؤشرات، 21 مهمة — محوّل من خطة استراتيجية 18 شهراً).
   **تنبيه:** توزيع المهام على الأشهر اجتهادي لأن الخطة الأصلية بلا توزيع شهري
   محدَّد — يحتاج مراجعة أحمد قبل الاعتماد النهائي.
4. أضف موظفي هداية من تبويب **الأعضاء** ببريدهم، وأسند لكل مهمة مسؤولاً رئيساً
   ومساندين من **لوحة المتابعة**.

## الفروقات عن نسخة غيث

| | غيث | هداية |
|---|---|---|
| مشروع Supabase | مستقل | مستقل جديد |
| نشر Vercel | مستقل | مستقل جديد |
| الشيفرة | نفس المستودع | نفس المستودع (بلا تفريع) |
| القالب الأولي | خطط غيث المرفوعة | `templates/خطة_هداية_قالب_تنفيذي.xlsx` |

أي تحديث لاحق على الشيفرة (إصلاح، ميزة جديدة) يُنشَر إلى النسختين بإعادة الـ Deploy
في كل مشروع Vercel على حدة — لا حاجة لتفريع (fork) المستودع ما دامت النسخة مطابقة.
